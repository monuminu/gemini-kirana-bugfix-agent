# Managed repair runner

`runJob(job, report, turns, evidence, config, hooks)` uses the current `@google/genai` Interactions API with `antigravity-preview-09-2026`. It sends the confirmed bilingual report, finalized original conversation, and only the selected inline JPEG evidence. It never places the Gemini key or GitHub credential in the agent prompt, environment, filesystem, network transforms, or tool results.

The runner was implemented against the pinned Google Gemini skill at commit `39d81f4c7de5e56631d07e4ea766d3fe9752ce5d`, the hosted [Antigravity agent](https://aistudio.google.com/docs/antigravity-agent.md), [managed agents quickstart](https://aistudio.google.com/docs/managed-agents-quickstart.md), [agent environments](https://aistudio.google.com/docs/agent-environment.md), [background execution](https://aistudio.google.com/docs/background-execution.md), and [agent credentials](https://aistudio.google.com/docs/agent-credentials.md) documentation. The project pins SDK `2.31.0`: requested `2.32.0` was not published on npm during setup. No older generation API is used.

## Provider lifecycle

The first request sets `background: true`, `store: true`, and provisions a remote environment that clones the public demo into `/workspace/repo`. Its outbound allowlist contains GitHub, raw GitHub, the GitHub API, and the npm registry. The prompt requires checkout of the confirmed immutable base commit before diagnosis. The only custom function is `publish_patch`, accepting `/workspace/fix.patch` and a short requested summary. Function arguments do not grant arbitrary command, file, URL, or GitHub authority.

The runner stores the interaction and environment IDs through the persistence hooks before polling. It polls every two seconds and recognizes normal `requires_action` pauses. It only dispatches unfulfilled `publish_patch` calls, ignoring filesystem functions already executed by the managed environment. Continuations use both `previous_interaction_id` and the same environment ID, and repeat the tools and system instruction because those are interaction-scoped.

Creation requests disable SDK retries. A lost create response, including an unresolved continuation that still has the previous interaction ID, is an unknown outcome, so the job becomes `needs_attention` and no duplicate agent is started. A restart with a known interaction ID reads that interaction. A restart after publication reads the saved patch, verifies it again, and rebuilds the recorded published commit. It does not open another PR. The initial candidate permits at most two further revisions after failed independent verification. The full deadline is capped at 15 minutes. Cancellation is checked every 500 ms and sends the provider cancel request, aborts local work, and removes any unfinished preview.

## Independent verification

The backend downloads exactly `/workspace/fix.patch` from the recorded managed environment, with a 1 MB patch limit. The patch validator accepts ordinary text changes to existing production `.ts`, `.tsx`, or `.css` files under `src/`. It rejects traversal, hidden paths, tests, test setup, manifests, workflows, secrets, binary changes, symlinks, mode changes, copies, renames, additions, and deletions. The backend applies `git apply --check`, applies the patch to a separate checkout, and confirms the resulting changed path set.

Verification independently clones the public repository at the immutable confirmed base SHA. Its original tests and all build configuration remain unchanged. The baseline must fail exactly the agreed test, `selling 2 kg sugar from 15 kg leaves 13 kg`; all other assertions must pass. The candidate then runs `npm test`, `npm run typecheck`, and `npm run build`. The provider's stdout is never accepted as proof.

The backend pulls public `node:22-bookworm-slim` anonymously using an empty task-local Docker CLI configuration and the existing local context socket, avoiding the user registry credential helper. All subsequent container operations use this same empty task-local CLI configuration and resolved local socket, so user Docker proxy/auth settings cannot inject credentials into a container. It records its content digest, and uses that digest for subsequent containers. Dependency preparation uses only baseline-lock packages with canonical npm-registry resolved URLs. Trusted host code downloads their exact tarballs anonymously from the known Microsoft public npm mirror, verifies the immutable lock SRI, and also records SHA-512 for each artifact. The task-local cache includes the Linux architecture’s required prebuilt binaries. No host installer, dependency lifecycle script, or candidate source is executed during these downloads. Docker then executes `npm ci --offline --ignore-scripts --no-audit --no-fund` with only the verified cache content mounted read-only. Every install, test, typecheck, and build container has no network. Neither the user’s npm cache nor npm configuration is mounted. All tests, type checking, and builds run with no network, an unprivileged user, dropped capabilities, no privilege escalation, a read-only container root, a temporary filesystem, CPU/memory/process limits, and read-only mounts for each tracked checkout input and installed dependencies. The working directory and build caches are ephemeral temporary filesystems; only separate test-result and built-artifact directories are writable. Each setup/check step re-hashes all tracked inputs, and the candidate JSON report must show the complete original assertion inventory passing without skipped or replaced tests. No host home directory, Docker socket, `.env.local`, or credential is mounted. Command exit codes and local logs are recorded, and a SHA-256 over the built artifact directory is saved in `Verification`.

## Publication

Publication runs in the backend with the GitHub credential. It checks that the current base branch still equals the confirmed base SHA before any mutation and again at each publication boundary. A stale base stops publication and requires a fresh confirmed report. GitHub blobs, a tree, and one commit are created with the confirmed base as the sole parent. A new `bugfix/kirana/<job-id>` ref is created without force-pushing.

If a branch already exists after a partial publish or lost response, its full tree and sole parent must equal the independently verified candidate and confirmed baseline. The runner looks up PRs by this exact head and reuses a matching open PR. It refuses unrelated or closed PRs. The created PR is a draft with a synthetic Hindi issue summarized in English, the relevant commands and immutable SHAs, and no transcript or images. The agent's requested summary is not used as public text.

## Exact-commit preview

The preview clones the actual published commit SHA, compares trusted build configuration with the verified baseline, installs locked dependencies in a container, and builds without network. Its built artifact SHA-256 must equal the independently verified candidate artifact. An isolated Node container serves only those static assets from a read-only mount at loopback `127.0.0.1:<previewPort>`; no repository server code is executed on the host or in the preview service.

The trusted browser driver resets the synthetic shop, chooses sugar, records a 2 kg sale, asserts `13 किलो`, reloads, and asserts that quantity again. External browser requests are blocked. Only after this browser proof does the job expose `preview_url` and become `completed`. It saves the screenshot and check result in the private job logs. A failed preview preserves the draft PR and becomes `needs_attention`; it does not claim the repair is complete. The configured preview port presents the newest successful preview, replacing only containers carrying this application's preview-port label.

## Local verification

Run `npm test -- tests/docker.test.ts tests/github.test.ts tests/runner.test.ts` for boundary, continuation, cancellation, revision-limit, stale-base, matching-branch, and duplicate-PR tests. Run `npm run typecheck` for the installed SDK surface and full application typing. These unit tests use dependency ports; they do not establish that a provider request, Docker build, GitHub publication, or browser run succeeded. Those outcomes require the live acceptance run and its persisted evidence.

To check an already running exact-commit preview manually, run `npx tsx scripts/preview-check.ts http://127.0.0.1:4310/ <private-artifact-directory>`. No cloud deployment is required. The preview is local, a PR remains a draft, and merging is outside the runner's authority.

Install the browser with `npx playwright install chromium` before the first repair (Linux system libraries: `npx playwright install --with-deps chromium`). The checker first uses an installed bundled executable, then the trusted Google Chrome channel.

For a saved draft whose preview is `needs_attention` or failed, run `npm run resume-preview -- <job-id>` after repairing the prerequisite. The command requires complete publication metadata, rejects cancelled/completed/active jobs and competing repairs, and gives only verification/preview a fresh 15-minute deadline with the original deadline retained for audit. A later correction to the conversation does not erase the immutable published patch's preview recovery. It never starts or continues an agent or publishes another PR.
